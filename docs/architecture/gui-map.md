## Уже решено (из ТЗ)

- Просмотр по умолчанию, управление — отдельное действие. Согласие сотрудника обязательно, обхода нет.
- Заявка обязательна перед всеми четырьмя действиями; вводится один раз в панели деталей (01) и действует на просмотр/управление/сообщение/logoff.
- Нет группы в токене — кнопка скрыта (ТЗ §8), не заблокирована. На макете показано состояние «все группы есть».
- Право Remote Control — одно (просмотр+управление), не делится на два (ТЗ §3). Разница view/control — только в клиенте (`/control`).
- Сообщение сохраняется в журнале целиком, не маскируется. Скриншотов нет.
- Значения — из INI, не из кода; в репозитории только пример без боевых имён.

## Поток завершения сеанса (logoff)

1. Специалист жмёт «Завершить сеанс» в панели деталей → открывается предупреждающее окно.
2. В окне — показатели узла/сеанса/ID, поле подтверждения и кнопки **LogOff** (danger, неактивна) и **Отмена**.
3. Подтверждение: ввести имя пользователя **без домена**; домен отсекается по обратному слешу (`CORP\user_iv` → `user_iv`). LogOff активируется при совпадении.
4. Нажатие LogOff → окно закрывается, отмены больше нет (logoff необратим).
5. Клиент опрашивает список сеансов **выбранного узла**, ожидая исчезновения пользователя с этим уникальным ID сеанса.
6. Когда пользователь пропал — уведомление внизу справа «Логофф выполнен». **Фокус окна не переходит** на уведомление.
7. Если за отведённое время сеанс всё ещё виден — предупреждение, а не успех.

### Политика опроса (решено)

- Интервал опроса — **2 секунды**.
- Предел ожидания — **40 секунд** (в рамках «не более 30–40 секунд»).
- Опрос идёт по `WTSEnumerateSessions` выбранного узла; совпадение по `(session_id, пользователь)`.
- Опрос **не пишется** в журнал (ТЗ §8: «Сам опрос в журнал не пишется»).
- Константы `LOGOFF_POLL_INTERVAL = 2s`, `LOGOFF_POLL_TIMEOUT = 40s` — в код, не в INI (значение внутреннее, не настройка фермы).

## Тень и мониторы (07)

Проблема: у сотрудника 2–3 монитора (разные разрешения/ориентация) → `mstsc /shadow` показывает весь стол широкой поверхностью, текст мелкий. Один удалённый монитор нативно не выбрать; окно shadow открывается на одном локальном мониторе. Разбор — `docs/research/2026-11-19-shadow-multimonitor-visualization.md`.

Варианты (макеты `07-shadow-display*.html`, v1–v4):

- **Обзор** (`smart sizing:i:1`) — весь стол в окне, видно всё, текст мелкий.
- **Детали 1:1** (`smart sizing:i:0`) — нативно + прокрутка к монитору, читаемо; рекомендуемый для чтения.
- **Разложить на свои мониторы** (`/span`) — условно, только одинаковые горизонтальные; для shadow не гарантировано.
- **Свой вьюер** — вне v1 (нужен свой RDP-стек).
- **Лупа ОС** (Win + «+») — дешёвый приём чтения без смены режима.

Что даёт наш клиент: пресет режима + размещение окна; временный `.rdp` + `mstsc <file> /shadow`, запоминание на узел.

Проверено (2026-11-19): smart sizing переключается **на лету** в меню окна mstsc (переподключение нужно только для смены разрешения). Встраивание сеанса в своё окно возможно двумя путями: `SetParent` (раскладка, не рендеринг) и `Windows.Graphics.Capture` (настоящий zoom/pan, но перерисовка с рамкой захвата и латентностью); RDP ActiveX для shadow не задокументирован. Макеты: `07-shadow-display.html` (v1), `-v2` (выборы + авто-промт), `-v3` (контекст к вопросам), `-v4` (пояснения вне окна, выбраны варианты), `-v5` (компоновка WGC-окна), `-v6` (F — основная концепция; управляемая мини-карта, помощь по функциям).

Решено (2026-11-19, макет v4):

- 7.1 Режим по умолчанию — **Детали 1:1** (нативно + прокрутка), «Обзор» по кнопке; переключение на лету.
- 7.2 Размещение окна — **на мониторе, где открыт RDS Shadow**.
- 7.3 Дополнительно — все: лупа ОС, мини-карта, запоминание на узел, памятка про меню.
- 7.4 Способ встраивания — **свой рендерер (WGC)**; SetParent отклонён. См. решение 0005.

Правило макетов: пояснения (почему/ограничения) — вне окна, отдельным блоком «не часть окна»; в окне — только операционные элементы (`ui-standard.md`).

Компоновка WGC-окна (v6, F — основная концепция): сеанс — в **заголовке**; режим и масштаб — в **подвале**; выбор монитора кнопками не делается. **Мини-карта** — кнопка «Мини-карта», `Ctrl+M`, и появление при масштабировании. Окно помощи — только функции окна с кратким описанием (без очевидного нативного UI). Подсказки: плашка на 5 с → «?» → панель. См. решение 0005.

## Контракт разметки (что уже нанесено)

- Семантика доступности: `role` (`navigation`, `listbox`/`option`, `dialog`, `status`), `aria-*` (`aria-label`, `aria-current`, `aria-selected`, `aria-labelledby`, `aria-modal`, `aria-live`, `aria-required`), `aria-hidden` на декоративных иконках.
- Стабильные хуки для проверок: `data-testid` (`search`, `session-list`, `session-row`, `ticket`, `action-view/control/message/logoff`, `connect-*`, `message-*`, `logoff-*`, `mode-*`).
- Вопросы и варианты: `data-q`, `data-variant`, `data-q-title`, `data-variants`, `data-recommended`.

## Приёмка вида (краткий чек-лист)

- Действие доводится с клавиатуры до конца; похожие действия — одинаково.
- Опасные действия (управление, logoff) — явные, fail-closed, с заявкой и подтверждением.
- Курсор/выбор списка — только фоном выбора, без лишних рамок.
