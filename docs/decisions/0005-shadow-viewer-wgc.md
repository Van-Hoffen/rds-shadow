# 0005 — Отображение теневого сеанса при нескольких мониторах: свой рендерер (WGC)

- Статус: принято 2026-11-19 (проект; код не написан)
- Тип: explanation

## Контекст

У сотрудника 2–3 монитора (разные разрешения, ориентация). `mstsc /shadow` показывает весь виртуальный стол одной широкой поверхностью; текст мелкий. Один удалённый монитор нативно не выбрать. Возможности разобраны в `docs/research/2026-11-19-shadow-multimonitor-visualization.md`.

## Решение

- Режим по умолчанию — **«Детали 1:1»** (нативно + прокрутка); «Обзор» — вписанный стол. Переключение — **на лету** в подвале окна рендерера; `mstsc` для захвата запускается с `smart sizing:i:0`. Смена разрешения — с переподключением. (F, WGC, принят за основную концепцию.)
- Окно сеанса открывается **на мониторе, где открыт `rds-shadow`**.
- Способ — **свой рендерер**: кадр окна `mstsc` захватывается `Windows.Graphics.Capture` (WGC) и рисуется в нашем окне; **zoom/pan/crop** по мониторам.
- Компоновка окна: сеанс в заголовке; режим и масштаб в подвале; выбор монитора кнопками не делается.
- Дополнительно: **мини-карта** (кнопка/`Ctrl+M`, показывается при масштабировании), запоминание режима и положения окна на узел. Горячие клавиши функций окна настраиваются в разделе «Горячие клавиши» настроек. Окно помощи описывает только функции окна.
- В окне поддержки — только операционные элементы; пояснения — вне окна (см. `ui-standard.md`).

## Почему так

- `mstsc` не даёт zoom/pan и не выбирает один удалённый монитор; WGC даёт настоящий контроль вида без своего RDP-стека.
- Smart sizing переключается на лету, поэтому режим «Обзор ⇄ Детали» можно менять без реконнекта.

## Отклонено

- Только `mstsc` + диалог — нет zoom/pan, остаётся мелкий текст (оставлено как запасной путь).
- `SetParent` — единое окно и раскладка, но не zoom/pan; риск кросс-процессного DPI.
- RDP ActiveX — обычный RDP, shadow не задокументирован.
- Свой RDP-стек — вне v1 по ТЗ.

## План реализации (поэтапно, нужен Windows-стенд)

1. **Запуск.** ✅ ядро готово: `rds-shadow-core::command::rdp_file` (`smart sizing:i:0`, `screen mode id:i:1`, `use multimon:i:0`) и `mstsc_shadow_args`; `platform::run_mstsc` пишет временный `.rdp` и запускает `mstsc <file> /shadow:<id>`. Покрыто юнит-тестами (22). ⏳ Проверить совместимость `mstsc <file> /shadow` на Windows-стенде (запасной путь — `Default.rdp`/реестр).
2. **Захват.** `IGraphicsCaptureItemInterop::CreateForWindow` по HWND окна `mstsc` (`EnumWindows`/поиск по заголовку/процессу), `Direct3D11CaptureFramePool`, сессия; кадр → текстура egui.
3. **Вид.** zoom/pan/crop, мини-карта (кнопка/`Ctrl+M`, при масштабировании), запоминание режима и положения окна на узел.
4. **Ввод (для управления).** Проброс координат/клавиш из нашего вьюпорта в окно `mstsc` — отдельная сложная задача; для просмотра не требуется.

## Риски

- WGC рисует жёлтую рамку захвата; скрыть нельзя — только принять.
- Латентность и нагрузка GPU; для управления в реальном времени может быть мало.
- Поиск HWND окна `mstsc` ненадёжен (заголовок/процесс); нужен тест на стенде.
- `CreateForWindow` — Win10 1903+; на старых сборках только системный picker.
- Проброс ввода сложен и не покрыт этим решением.
- Код не написан; успех нельзя заявлять до прогона на Windows-стенде.

## Запасной путь

Если WGC окажется дорогим/медленным — «`mstsc` + диалог»: `.rdp` с `smart sizing:i:0` (Детали 1:1) и живое переключение в меню `mstsc`.
