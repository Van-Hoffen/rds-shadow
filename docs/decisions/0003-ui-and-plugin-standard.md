# 0003 — Стандарт интерфейса и модель плагинов (по depesha)

- Статус: принято 2026-11-19
- Тип: explanation

## Решение

Принять два стандарта из проекта `fgbm/depesha`, адаптированные под RDS Shadow (Rust + egui):

1. **Стандарт интерфейса** (`docs/architecture/ui-standard.md`): HTML-макеты как единственный источник визуальной истины, машиночитаемый контракт `data-*`/`aria-*`/`role=`, baseline-гард инвариантов, детерминированные скриншоты. Объём — «макеты + инварианты»; `egui_kittest`/`accesskit` — отдельная задача.
2. **Модель плагинов** (`docs/architecture/plugin-model.md`): ядро vs плагины, стабильный контракт `plugin-api`, точки расширения, права/согласие, два вида плагинов (built-in теперь, community/WASM позже). Реализация отложена до стабилизации модели.

## Почему так

- Интерфейс, заданный машиночитаемым артефактом, проверяем агентами LLM без человека: по разметке, контрактным атрибутам и скриншотам.
- Разделение ядро/плагины держит ядро обозримым (список/shadow/сообщение/logoff/журнал), а изменчивое — за контрактом.
- Права/согласие и `defaultOff`/`defaultOn` переносят различие «вред vs предпочтение» в дисциплину продукта.

## Что не переносится

- TS/Svelte-компоненты, Web Worker `ext://`, Tauri IPC, словари `{en,ru}` — специфика web-стека depesha.
- WebDriver/Svelte e2e — нативный egui-клиент проверяется иначе.

## Отклонено

- Сразу реализовать WASM-песочницу community-плагинов — преждевременно до стабилизации контракта.
- Сразу проектировать `egui_kittest`-харнесс — отдельная задача после утверждения pipeline.
- Копировать код depesha буквально — разные стеки и предметная область.

## Остаточный риск

- Набор точек расширения плагинов — черновой; уточняется при проектировании контракта.
- Baseline-гард инвариантов для HTML-макетов пока не в CI (pipeline не утверждён).
