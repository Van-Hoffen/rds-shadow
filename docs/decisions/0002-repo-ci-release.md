# 0002 — Каркас репозитория, CI и релиз

- Статус: принято 2026-11-18
- Тип: explanation

## Решение

Репозиторий `Van-Hoffen/rds-shadow`, ветка `main`. Cargo workspace из трёх крейтов:

- `rds-shadow-core` — платформенно-нейтральное ядро: INI, события, JSONL, фильтры, аргументы `mstsc`. Тесты идут на Linux и Windows.
- `rds-shadow` — Windows-клиент. Код за `cfg(windows)`, на Linux собирается заглушка. Это позволяет CI проверять ядро без Windows-раннера.
- `rds-shadow-audit` — кроссплатформенный просмотрщик JSONL.

CI: `.github/workflows/ci.yml` — fmt, clippy `-D warnings`, тесты на Linux и Windows, release-сборка на Windows.

Релиз: `.github/workflows/release.yml` по тегу `v*`:
- проверка, что тег совпадает с версией workspace;
- Windows zip: клиент, просмотрщик, пример INI;
- Linux tar.gz: просмотрщик;
- GitHub Release с автоматическими заметками.

## Почему так

- Windows-клиент нельзя проверить на Linux-раннере, но большая часть логики (конфиг, аудит, гейты аргументов) вынесена в ядро и покрыта тестами.
- Версия одна на workspace: релиз не может уехать с разными версиями крейтов.
- Приватность: боевые имена узлов, брокера и групп в git не попадают; пример INI пустой.

## Отклонено

- Отдельные независимые версии крейтов — лишняя сложность для v1.
- Публикация в crates.io — внутренний продукт, `publish = false`.
- Подпись бинарников в CI — нужен корпоративный сертификат, отдельная задача.
- Автоматический тег при каждом коммите — релиз должен быть осознанным.

## Остаточный риск

- Windows-код проверен кросс-компиляцией `x86_64-pc-windows-gnu` локально, но не запускался на Windows. Первый запуск — только на стенде, без logoff чужого сеанса.
- Брокер: обнаружение коллекций в этом каркасе не реализовано, режим `broker` требует заполненного `[servers] list`.
