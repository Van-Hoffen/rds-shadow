# Research Brief — Визуализация shadow-сеанса с 2–3 мониторами

- Date: 2026-11-19
- Question: Какими способами можно управлять визуализацией теневого RDS/RemoteApp-сеанса, когда у сотрудника 2–3 монитора (разные разрешения, ориентация, соотношения сторон), а окно `mstsc /shadow` открывается широким и всё в нём мелкое.
- Scope / out of scope: возможности клиента `mstsc` и ОС. Не реализация своего RDP-стека (вне v1 по ТЗ).

## Findings

- `mstsc /shadow` показывает **весь** виртуальный стол сотрудника (все его мониторы) одной широкой поверхностью. Нативно выбрать один удалённый монитор нельзя. — Microsoft Q&A (mstsc to only display a specific monitor) — high
- Теневое окно при shadow **всегда открывается на одном локальном мониторе**; разложить само shadow на свои мониторы штатно нельзя. — Windows OS Hub (RDP session shadow) — medium
- **Smart sizing** (`smart sizing:i:1` в `.rdp` или меню окна) масштабирует картинку под размер окна, сохраняя пропорции; разрешение сеанса не меняется. Без него окно меньше стола → полосы прокрутки, просмотр 1:1. — woshub, superuser — high
- Для мультимониторного сеанса рекомендуют **отключить масштабирование** и прокруткой переходить к нужному монитору. — RDPSoft SuperShadow — high
- `/span` растягивает стол на локальные мониторы, но только если они **одинакового разрешения и стоят в ряд**; вертикально нельзя. Для shadow эффект не гарантирован (см. выше про один монитор). — Microsoft Learn mstsc — high
- `selectedmonitors` / `use multimon` выбирают **локальные** мониторы клиента, не удалённые. — Microsoft RDP properties (через itechguides) — high
- `dynamic resolution` (разрешение под размер окна на лету) есть в новом клиенте «Windows App», **не в mstsc**; для shadow не применимо. — superuser/ITPro — high
- Shadowing RemoteApp-сеанса имеет известные странности (окна приложения на удалённом столе, «чёрные» окна при /multimon). — microsoftplatform.blogspot, FreeRDP #5454 — medium
- Старый кейс: `error 120` при shadow с одномониторного клиента на мультимониторный сеанс. Современные серверы это переживают, но проверять на стенде. — microsoftplatform.blogspot — medium

## Options

1. **Обзор (fit).** `smart sizing:i:1`; весь широкий стол вписан в окно. Плюс: видно всё и курсор. Минус: текст мелкий. Это текущее поведение.
2. **Детали 1:1 (нативно + прокрутка).** `smart sizing:i:0`; окно меньше стола → полосы прокрутки, пиксель в пиксель, прокрутка к нужному монитору. Плюс: читаемо. Минус: не видно всё сразу, нужна навигация.
3. **Разложить на свои мониторы (`/span`).** Плюс: почти нативно по ширине. Минус: только одинаковые горизонтальные мониторы; для shadow не гарантировано.
4. **Лупа ОС (Win + «+»).** Плюс: без кода. Минус: ручной режим, неудобно постоянно.
5. **Свой вьюер (zoom/pan/выбор монитора).** Плюс: полный контроль. Минус: нужен свой RDP-стек — вне v1 (ТЗ).

## Fit for this project

- applicable — варианты 1–2 как **пресеты в диалоге запуска** нашего клиента: пишем временный `.rdp` с нужным `smart sizing`/`screen mode` и запускаем `mstsc <file> /shadow:<id>`, либо ставим `Default.rdp`; плюс размещение окна (`SetWindowPos`) на выбранном локальном мониторе. Запоминать режим на узел.
- partial — вариант 3 (`/span`): только при совпадении разрешений; проверить на стенде, что shadow вообще растягивается.
- no — вариант 5: свой вьюер вне v1.

## Risks

- `mstsc <file.rdp> /shadow:<id>` — совместимость файла с `/shadow` нужно проверить на стенде; запасной путь — правка `Default.rdp` и `winposstr` в реестре.
- Прокрутка через полосы mstsc — ручная; программный «прыжок к монитору» (send scroll/позиционирование) хрупок.
- Раскладку мониторов сотрудника надёжно узнать нельзя; «карта мониторов» будет иллюстративной, а не точной.

## Recommend next

- Принять два пресета (Обзор / Детали 1:1) + размещение окна; документировать лупу ОС; проверить `.rdp`+`/shadow` и `/span` на Windows-стенде.
- Макеты вариантов — `gui_html/rds-shadow/07-shadow-display.html`.

## Дополнение (2026-11-19): smart sizing на лету и встраивание

### Smart sizing — на лету?

- В оконном режиме `mstsc` smart sizing включается/выключается в меню окна (значок слева вверху / правый клик по строке подключения), **без переподключения**. — woshub, superuser, spiceworks — high
- Переподключение нужно для **смены разрешения сеанса** (`desktopwidth`/`desktopheight`/`dynamic resolution`) — это другое. — superuser, tsplus — high
- Наш клиент задаёт стартовое состояние через `.rdp` `smart sizing:i:1`, а дальше пользователь переключает в меню mstsc. Программно дёргать меню — ненадёжно.

### Встраивание сеанса в своё окно

- **`SetParent`** — переподчиняет top-level окно `mstsc` своему окну: раскладка (позиция/размер) есть, рендеринг не меняется; кросс-процессный DPI-конфликт может форсировать сброс дочернего процесса. — Microsoft Learn SetParent — high
- **`Windows.Graphics.Capture`** — захват окна `mstsc` в D3D11-текстуры и рендер в своём окне с произвольным zoom/pan/crop. Жёлтая рамка захвата, проброс ввода отдельно, латентность; окна Win10 1803+, `CreateForWindow` 1903+. — Microsoft Learn WGC, блог Windows — high
- **DWM thumbnail** (`DwmRegisterThumbnail`) — живой превью окна в прямоугольник; для превью, не для полноценного zoom/pan; destination — top-level своего процесса. — Microsoft Learn DWM — high
- **RDP ActiveX** (`mstscax.dll`, `MsTscAx`/`MsRdpClient`) — встраиваемый RDP-клиент (Connect/Disconnect/DesktopWidth/UseMultimon), но это обычный RDP; поддержки shadow (`/shadow`) не задокументировано. — Microsoft Learn MsTscAx — high; отсутствие shadow — medium

Вывод: «вписать сеанс в своё окно и манипулировать видом» реально двумя путями — `SetParent` (раскладка) и `WGC` (zoom/pan, но перерисовка и ввод). Полноценный контроль с вводом — только свой RDP-стек (вне v1).
